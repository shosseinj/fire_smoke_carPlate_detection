EXECUTIVE SUMMARY

خلاصه مدیریتی پروژه

هدف اصلی، تبدیل مجموعه‌ای از دوربین‌ها به یک زیرساخت قابل توسعه برای اجرای هم‌زمان چند مدل هوش مصنوعی با تأخیر کنترل‌شده است.

۰۱

مسئله‌ای که حل می‌شود

دریافت چندین جریان ویدئویی، تخصیص متفاوت وظایف به هر دوربین، جلوگیری از عقب‌ماندن صف پردازش و ارائه نتیجه قابل مصرف برای داشبورد، API و پایگاه داده.

راهکار اصلی

یک Task Router با Worker مستقل برای هر وظیفه، صف Latest-only منصفانه، Micro-batching و اتصال مستقیم به DeepStream؛ بنابراین OCR کند، مسیر آتش و دود را متوقف نمی‌کند.

وضعیت فعلی

ساختار نرم‌افزار کامل، تست‌پذیر و دارای Dashboard، Swagger، ثبت رخداد، مدیریت مدل و تنظیمات آنلاین است. آزمون‌های کد موفق‌اند؛ اما سنجه‌های دقت مدل بدون وزن و مجموعه ارزیابی قابل ادعا نیستند.

دامنه گزارش

این گزارش بر اساس کد منبع، تنظیمات، تست‌ها و مستندات داخل فایل ZIP تهیه شده است. وزن‌های کامل مدل و گزارش آموزش/اعتبارسنجی داخل آرشیو نبودند؛ بنابراین درباره mAP، Precision، Recall یا نرخ OCR عدد ساختگی ارائه نشده است.

۰۳

قرارداد فریم

هر دور استخراج شامل لیست فریم‌ها و لیست دقیق Source ID است. سامانه هویت دوربین را از موقعیت آرایه حدس نمی‌زند؛ در نتیجه فعال/غیرفعال شدن دوربین ترتیب را خراب نمی‌کند.

round N → [frame_cam1, frame_cam2, ...]
source_ids → ["camera-01", "camera-02", ...]

یک فریم، چند وظیفه

اگر دوربین هر دو Task را داشته باشد، همان آرایه NumPy به دو Worker ارجاع داده می‌شود. کپی فقط هنگام رسم یا نیاز مدل انجام می‌شود و هزینه حافظه کنترل می‌گردد.

اعمال تغییرات آنلاین

تغییر Task، فعال‌سازی، URI، ابعاد، Threshold و انتخاب مدل بدون Restart کل سرویس اعمال می‌شود؛ Pipeline همان دوربین فقط در صورت نیاز بازسازی می‌گردد.

DEPLOYMENT

استقرار، DeepStream و زیرساخت GPU

مسیر تولید برای Linux/NVIDIA طراحی شده است. OpenCV نقش Fallback توسعه‌ای دارد و برای تعداد زیاد RTSP گزینه اصلی نیست.

۱۱

Docker و NVIDIA

Compose دسترسی GPU، حافظه اشتراکی ۲GB، Volume برای Data/Weights/Media و Port 8000 را تنظیم می‌کند. قابلیت‌های compute، utility و video فعال‌اند.

پایداری Stream

RTSP با TCP، latency پیش‌فرض ۵۰۰ms، reconnect نامحدود و Retry سه‌ثانیه‌ای اجرا می‌شود. خرابی یک دوربین Pipeline سایر منابع را متوقف نمی‌کند.

Lazy Loading

سرویس حتی بدون وزن مدل بالا می‌آید و مدل در نخستین Batch بارگذاری می‌شود. Mock Mode امکان تست Router بدون GPU و وزن را فراهم می‌کند.
