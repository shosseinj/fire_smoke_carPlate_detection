Legacy-to-Current App Migration Report
=======================================

Source archive: old.zip
Current project: app/api, app/core, app/processors, tests

Purpose
-------
Examine the overlapping applications in old.zip and the current project one by
one, then make the current APIs, endpoints, request schemas, response shapes,
permissions, persistence, and side effects as compatible with the legacy
project as safely possible.

No application code was changed while preparing this report.

Recommended Migration Order
----------------------------

1. Authentication
   Legacy area: backend/app/routers/auth.py
   Current area: app/api/auth.py, app/api/auth_schemas.py
   Scope: login, token, refresh, logout, users, roles, current user, password
   changes, permissions, and legacy response compatibility.

Highest-Priority Compatibility Gaps
------------------------------------

- Plate-log item-level GET, PATCH, and DELETE operations.
- Import-progress routes and their current replacement, if any.
- Project-info/version routes and their current replacement, if any.
- Exact legacy response shapes for locations, personnel, plates, and model
  exports.
- Legacy integer camera IDs versus current string source IDs.
- Legacy base64 personnel-image responses versus current media/file URLs.
- Legacy personnel-request statuses versus current internal statuses.
- Legacy settings reset behavior versus partitioned current settings.

Per-App Completion Checklist
----------------------------

For each numbered app:

1. Inventory every legacy route and method from old.zip.
2. Match each route to the current router, store, service, or mark it missing.
3. Compare request fields, defaults, enums, validation, and authentication.
4. Compare status codes, response fields, nesting, timestamps, and errors.
5. Verify persistence, foreign keys, files, vectors, events, and cleanup.
6. Implement only the confirmed compatibility changes.
7. Add focused tests for success, invalid input, permissions, not-found, and
   downstream side effects.
8. Run the focused tests before moving to the next app.
9. Run cross-module regression tests after completing each phase.

Important Constraints
---------------------

- Preserve the current project's real-time architecture unless compatibility
  requires a verified change.
- Do not expose credentials, private camera URLs, tokens, or sensitive payloads.
- Do not delete or rewrite unrelated worktree changes.
- Do not claim legacy parity until routes, schemas, responses, permissions,
  persistence, and connected outputs have been tested.
- Unselected or not-yet-reviewed apps should remain unchanged until their step.
